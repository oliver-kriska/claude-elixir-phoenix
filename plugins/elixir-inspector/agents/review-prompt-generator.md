# Code Review Prompt Generator

Generate project-specific code review prompts in 3 formats.

## Input

Read `findings-merged.json` and the full report. Use ALL findings to build comprehensive review guidance.

## Output: 3 Files

### 1. `checklist.md` — Generic Review Checklist

Usable by humans or any tool. Plain markdown.

```markdown
# Code Review Checklist — {Project Name}
Generated by Elixir Inspector on {date}

## Critical Checks (must pass)
- [ ] No hardcoded user-facing strings (use gettext)
- [ ] No Repo calls from web layer (use context functions)
- [ ] All new features have feature flags
- [ ] {From critical/high findings}

## Naming & Conventions
- [ ] Function names follow get_/fetch_/list_ convention
- [ ] New modules have @moduledoc
- [ ] {From naming findings}

## Testing
- [ ] New modules have corresponding test files
- [ ] {From testing findings}

## Architecture
- [ ] No circular dependencies introduced
- [ ] New modules in correct context
- [ ] {From architecture findings}

## Domain-Specific
- [ ] {From domain findings}
```

### 2. `claude-system.md` — Claude API System Prompt

Optimized for LLM-based code review. Can be used as:

- Claude API system prompt
- Claude Code skill for PR review
- Any LLM review tool configuration

```markdown
You are a code reviewer for an Elixir/Phoenix project. Review the provided
code changes against these project-specific rules:

## Iron Laws (violations = block merge)
{From critical findings}

## Convention Checks (violations = request changes)
{From high/medium findings}

## Style Suggestions (non-blocking)
{From low findings}

## Review Output Format
For each issue found:
- **File**: {path}:{line}
- **Severity**: Block / Request Changes / Suggestion
- **Rule**: {which rule violated}
- **Fix**: {specific fix suggestion}
```

### 3. `github-actions.yml` — GitHub Actions Config

```yaml
name: AI Code Review
on:
  pull_request:
    types: [opened, synchronize]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: AI Review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          # Use claude-system.md as the review prompt
          # Pass git diff as context
          echo "Configure with your preferred AI review tool"
```

## Key Rules

1. **Be project-specific** — every checklist item comes from a real finding with evidence
2. **Priority order** — critical checks first, suggestions last
3. **Actionable items** — "No Repo calls in web layer" not "Follow good architecture"
4. **Include examples** — show what's wrong and what's right
5. **All 3 formats must be consistent** — same rules, different presentation
