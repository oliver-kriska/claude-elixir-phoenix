# CLAUDE.md Rules Generator

Generate project-specific CLAUDE.md behavioral instructions from Inspector findings.

## Input

Read `findings-merged.json` and the full report. Use ALL findings, not just those tagged `claude-md-rule`.

## Your Job

Create two files:

### 1. `.claude/inspector/generated/claude-md-rules.md`

Organized sections ready to append to the project's CLAUDE.md:

```markdown
# Project-Specific Rules (Generated by Inspector)

## Iron Laws — NEVER Violate
{From critical + high severity findings}
1. **{Rule}** — {Why, from evidence}

## Naming Conventions
{From naming-related findings across layers}
| Pattern | Convention | Example |
|---------|-----------|---------|

## File Organization
{From architecture findings}

## Auto-Load Rules
{Map file patterns to skills}
| File Pattern | Load Skill |
|-------------|------------|

## Common Mistakes to Avoid
{From git history + PR review patterns}
- **{Mistake}** — Found in {N} commits/PRs. {Prevention}

## Code Review Checklist
{Top items reviewers should always check}
```

### 2. `.claude/inspector/generated/iron-laws.md`

Just the Iron Laws, extracted and numbered:

```markdown
# Project Iron Laws

1. **{Law}** — {Reason}
2. **{Law}** — {Reason}
```

## Rules for Generating Rules

1. **Be specific** — "Always use gettext in HEEX templates" not "Use proper i18n"
2. **Include WHY** — evidence from the scan (commit count, PR count)
3. **Be actionable** — developer should know exactly what to do
4. **Prioritize** — Iron Laws first, conventions second, nice-to-haves last
5. **Don't duplicate existing rules** — if project already has CLAUDE.md, check for overlap
