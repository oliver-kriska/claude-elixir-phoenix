Order rationale:
- **Dependencies first.** Skeleton → data layer → wire edge → fixtures → identity → everything that checks permissions.
- **02 is the riskiest core:** auth crypto, a forced re-login, and password-hash compatibility for every existing user (C-02, C-11, C-14).
- **05 is the destructive and authorization-heavy write path.** The read paths (04, 07) are low risk.
- **09 closes the roadmap:** conversion on a copy, `VACUUM INTO` backup and restore, rollback hand-back, and operator tasks.

## 00a Skeleton, config, Repo

**Goal**: A Phoenix 1.8 JSON-only release boots on the kept SQLite file. Config comes from fail-closed env vars, CORS is allowed only for the configured origins, and the supervision tree has no domain processes (F-14, part).

**Ledger rows**:

| Row | Verdict | Target |
|-----|---------|--------|
| R-01 | REPLACE | one Phoenix release on Bandit |
| R-02 | DELETE | |
| M-03 | DELETE | signal registration |
| M-35 | DELETE | django_extensions |
| M-36 | MAP | `runtime.exs` |
| M-37 | DELETE | |
| C-44 | REPLACE | env contract, DV-06 |
| R-10 | KEEP | the SQLite file, through the writer Repo |
| R-13 | DELETE | |
| M-31 | REPLACE | Corsica |
| M-32 | REPLACE | `:api` pipeline |
| C-51 | DELETE | secure headers, DV-13 |

**Contracts**:
- C-44: changed, ASSUMED.
- C-31: keep the defaults, configurable.
- C-51: relaxed.

**Acceptance criteria**:
- Boot succeeds with all required env set, and the release has no HTML, LiveView, assets or mailer.
- Boot fails closed when any of these hold:
  - `JWT_SECRET` is missing or shorter than 32 bytes
  - `SECRET_KEY_BASE` is shorter than 64 bytes
  - `DATABASE_PATH` or `PHX_HOST` is missing
  - `CORS_ORIGINS` contains `*`
- The writer Repo opens `DATABASE_PATH` with `pool_size: 1`, `BEGIN IMMEDIATE`, `busy_timeout: 5000` and `synchronous: FULL`. WAL is pending DV-22. A boot task logs `sqlite_version()`, `journal_mode` and `foreign_keys` (VO-04).
- A CORS preflight from `http://localhost:4000` with an `authorization` header is allowed; `http://evil.test` is refused; credentials are not allowed (VO-09).
- `/api` responses carry Phoenix secure browser headers.

**Exit gate**: `/rewrite:verify 00a`

## 01 Oracle fixtures and baseline

**Goal**: Capture legacy-produced vectors and the perf baseline on an isolated, non-production legacy build at 29c9d42831fa, using synthetic users only. `test/fixtures/legacy/PROVENANCE.md` records each vector's source, revision, capturer and test secret.

Vectors to capture:
- a Django 1.10 `pbkdf2_sha256` hash (VO-01)
- HS256, HS384, HS512 and `none` tokens signed with a **test** key (VO-02)
- `.schema` (VO-06)
- Python `slugify` vectors (VO-07)
- golden error bodies per route (VO-10)
- `tagList` order (VO-11)
- feed route shadowing (C-35)

Baseline: p95 and throughput for article list, single article, feed and login at c1/c16/c64. Also the Repo topology measurement (VO-12, OD-4).

**Blocked by**: the user's permission to run legacy (Q7). The plugin never runs it. The user runs it on a machine they control, or approves the run explicitly.

**Exit gate**: every vector has provenance. No production secret or customer data is captured. The legacy `SECRET_KEY` is never used to mint fixtures.

## 02a Token identity · 02b Register and log in · 02c Own account

**Goal (F-01..F-04)**:
- Register: user and profile are created atomically.
- Log in: Django hashes verify, with one timing-safe failure path.
- Every request:
  - parses `Token <jwt>`
  - verifies HS256 only, using the new key
  - re-checks `is_active`
  - builds `%Scope{user, profile}`
- Own account: GET and PUT `/api/user` return a fresh token.

**Blocked by**:
- **UNDECIDED rows:** C-16 (02a), C-40 (02b), C-37 (02c).
- **OD-2:** the PBKDF2 iteration count, which conflicts with the login perf gate.
- **DV-01:** ASSUMED forced re-login at cutover.

**Exit gate**: `/rewrite:verify 02a` / `02b` / `02c`. VO-01 and VO-02 must pass on slice-01 vectors.

## 04 Read articles and tags

**Goal (F-09, F-10)**:
- Single article.
- Filtered list (`author`, `tag`, `favorited`) with limit/offset paging: default 20, no max.
- Newest-first ordering with a deterministic tiebreak (DV-23).
- Viewer-relative fields batched per page, not per row (M-22).
- Tags list.

**Acceptance**: C-20 exact keys, no `id`. `tagList` order per VO-11.

**Blocked by** (handoff only): ADR-009 proposed; DV-18, DV-23 pending; DV-P3 open.

## 08 Comments

**Goal (F-13)**:
- Add a comment (201).
- List newest first, paged at 20 with `commentsCount`; an unknown slug returns 200 with an empty list.
- Delete is allowed only for the comment's author and only when the comment belongs to the URL's article (C-33, ASSUMED change). It returns 204 with an empty body.

**Blocked by** (handoff): DV-04, DV-P6 pending. C-41 (decided in 00c) governs the comment `author`-key crash.
