## High-Risk Mechanisms

### M-04 JWT authentication backend
**Anchor**: `conduit/apps/authentication/backends.py:10-93`; settings.py:147. **Purpose**: stateless token auth for SPA/mobile RealWorld clients (evidence: docstring backends.py:14-31; README RealWorld spec).
**Guarantees**: authorization re-checked on every request (JWT signature + `exp`, user row exists, `is_active`). Visibility: a deactivation takes effect on the next request. Headers with one part or more than two parts, and any prefix other than `token` (case-insensitive), give an anonymous request rather than an error. A malformed or expired token gives `AuthenticationFailed` → **403** even on `AllowAny` endpoints such as `GET /api/articles`.
**Failure history**: history absent. Known weaknesses (inferred): algorithm not pinned in `jwt.decode`; bare `except:` hides the error type.
**Candidate**: REPLACE → `ConduitWeb.Auth` plug (Joken verify, HS256 pinned) loading `%Scope{}`; pipelines `:optional_auth` / `:require_auth`. **Why not MAP**: DRF's authenticator chain plus `request.user` mutation has no Phoenix analogue; the plug is the conventional shape. Status code and bad-token-on-public behavior depend on Q2.

### M-05 / M-06 JWT issuance and `SECRET_KEY`
**Anchor**: `authentication/models.py:100-138`, `settings.py:23`. **Purpose**: issue `{id, exp}` HS256 tokens valid for 60 days (documented docstring).
**Guarantees**: no revocation, no `iat`, no rotation; a token is re-minted on every user response. The key is committed in the repo.
**Candidate**: REPLACE issuance with Joken; KEEP the legacy key value via env for one token lifetime (≤60 days) if in-flight sessions must survive cutover, then rotate. **Open**: do any clients decode the payload (`id`), and must existing tokens survive cutover? (Q5)

### M-08 / M-09 / M-10 Response envelope and error contract
**Anchor**: `core/renderers.py`, `core/exceptions.py`, settings.py:143-146. **Purpose**: RealWorld wire format (documented: README, comments).
**Guarantees**: success `{"article": {...}}`, list `{"articles": [...], "articlesCount": n}` (no next/previous); validation errors 400 `{"errors": {...}}` with non-field key `"error"`; NotFound keyed by model verbose_name (`article`, `comment`, `profile`), or `detail` for views with no `queryset` (favorite, follow). Auth errors take neither path: 403 plus `{"<label>": {"detail": "..."}}`. Example: `GET /api/user` without a token returns `{"user": {"detail": "Authentication credentials were not provided."}}` (inferred).
**Candidate**: MAP → Phoenix JSON modules + `FallbackController`, frozen by golden files. **Why not REPLACE with Phoenix defaults**: 422 and `{"errors": {"detail": ...}}` would silently change the contract (Iron Law 7). The quirks need dispositions (Q2).

### M-27 Missing ownership authorization (defect)
**Anchor**: `articles/views.py:87-106` (update), `:144-157` (comment destroy). **Purpose**: gate writes on authentication (inferred); the RealWorld spec expects author-only edits and deletes.
**Guarantees today**: any authenticated user may edit any article or delete any comment by id, even through another article's URL.
**Candidate**: REPLACE → scope-checked context functions returning `{:error, :forbidden}` (strengthening). Porting the legacy behavior unchanged would carry a security hole into the new system. Contract class `defect`; it needs user approval as a behavior change (Q3).

### M-28 Route shadowing and route gaps
**Anchor**: `articles/urls.py:10-27`. **Purpose**: RealWorld paths (inferred).
**Guarantees today (inferred)**: `/api/articles/feed` resolves to the article-detail route (slug `feed`) and returns 404 `{"errors": {"article": "An article with this slug does not exist."}}`. Only `/api/articles/feed/` reaches the feed. There is no `DELETE /api/articles/:slug` and no PATCH. Usernames containing `-` or `.` get no profile route.
**Candidate**: MAP → explicit Phoenix routes. Phoenix ignores trailing slashes, so the port fixes the shadowing by default. That is a behavior change with no named consumer of the old behavior; record it as `defect` → `change`. Low confidence because the claim comes from reading the code; confirm with an isolated run or a client trace (Q1).

### M-01 / M-21 Non-atomic multi-write paths
**Anchor**: `authentication/signals.py:8`, `articles/serializers.py:44-54`, `authentication/serializers.py:139-176`; no `ATOMIC_REQUESTS`. **Purpose**: profile-per-user invariant (documented).
**Guarantees today**: autocommit. If the profile insert fails, a user remains with no profile, and every later authenticated request 500s on `request.user.profile`. Article create can commit with only some of its tags.
**Candidate**: REPLACE → `Ecto.Multi` + `Repo.transact/2` per operation. This strengthens the guarantee; record it in the ledger.

### M-25 Self-follow identity bug
**Anchor**: `profiles/views.py:63`. **Purpose**: forbid self-follow (documented error string). **Defect**: `is` on ints works only for pk ≤ 256 (CPython small-int cache; inferred). **Candidate**: MAP with `==` and record the fix as a behavior change.

## Implicit Framework Behavior

The port must re-provide these explicitly, or record their removal:

1. **Autocommit, no request transaction** (M-21). Today partial writes are possible; the target is atomic per operation (strengthening).
2. **`Meta.ordering` on every list** (M-12). Add explicit `order_by`; User has no default order.
3. **Python-side `auto_now`/`auto_now_add`** (M-11) and **Python-side CASCADE** (M-26). The DB has no defaults and no ON DELETE actions.
4. **`""` instead of NULL** for `Profile.bio`/`image` (`blank=True`). Ecto's default `empty_values` would turn `""` into nil → use `empty_values: []`.
5. **DRF unique validators** run a SELECT before the INSERT (M-19). Replace them with `unique_constraint/3` and pass Django's index names via `name:`.
6. **ModelBackend**: rejects inactive users, equalizes timing for unknown emails, and auto-rehashes on login when PBKDF2 iterations change (M-16).
7. **403 instead of 401** for auth failures, because M-04 has no `authenticate_header` (M-10).
8. **DRF content negotiation**: the browsable API and form/multipart parsers are on where `renderer_classes` is not overridden (M-34).
9. **Django 1.10 M2M direct assignment** on article update replaces the whole tag set (M-38).
10. **`X-Frame-Options: SAMEORIGIN`** on every response (M-32), incidental.
11. **`USE_TZ=True`, `TIME_ZONE='UTC'`**: SQLite stores naive UTC text. The Ecto type must read it as UTC (`:utc_datetime_usec`).
12. **CPython small-int caching** silently made M-25 work for small ids, a platform accident.
