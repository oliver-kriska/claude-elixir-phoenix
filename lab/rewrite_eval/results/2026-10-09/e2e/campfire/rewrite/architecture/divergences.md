# Divergences — every behavior that changes

Every row is **pending**. Nothing has been approved, and `--auto` mode cannot approve. "Strengthened" rows still change behavior that someone may observe, so they need approval too (Iron Law 7). Consumers come from `analysis/contracts.md` and `analysis/features.md`.

| ID | Legacy behavior | New behavior | Reason | Consumers | ADR | Ledger | Approval |
|----|-----------------|--------------|--------|-----------|-----|--------|----------|
| DV-01 | Message and body commit first. Unread marking, the FTS row and the push enqueue run after commit as separate steps; a crash in between loses them. A Redis outage returns 500 for a saved message | Message, body, FTS row, room touch, unread marking and job intents commit together or not at all | closes crash windows; Oban insert in the same transaction | sidebar unread, search, push users, bots | ADR-005, ADR-002 | M-01, M-02, C-13 | pending |
| DV-02 | Jobs live in non-persistent Redis and are lost on any restart. Push overflow beyond a 10k queue is silently dropped | Job enqueue is durable in `oban_jobs` and survives crashes and deploys. No push overflow drop; the backlog waits, bounded by DV-03 | Oban replaces Resque; the charter retires Redis | bot endpoints, push users | ADR-006 | M-20, M-22, M-25, R-24 | pending |
| DV-03 | Old jobs never run late: they are lost on restart | Webhook and push jobs older than 10 minutes at pickup are cancelled (`{:cancel, :stale}`). This includes jobs restored from a backup | prevents hour-old webhooks and pushes after outages or restores | bots after outages, restores | ADR-006 | M-20, M-21, R-24 | pending |
| DV-04 | Deactivate and ban disconnect sockets **inside** the transaction, so a rollback has already disconnected the user | Disconnect is broadcast after commit for every caller | no disconnect on a rolled-back change; no reconnect race | admins, banned or deactivated users | ADR-009 | M-07, M-16, M-17 | pending |
| DV-05 | Presence is stored in `memberships.connections` / `connected_at`. Counters are lossy across tabs, a dead connection keeps counting for up to 60 s, and the counters reset at boot | In-memory Registry: exact per-subscription count, removed immediately when the connection dies, 60 s refresh window kept. The columns are **no longer written** (retire after the rollback window) | single-writer load (one write per tab per 50 s); exactness | members (unread, push suppression); Rails after rollback resets the columns at boot | ADR-007 | M-28, R-05 | pending |
| DV-06 | The `_campfire_session` cookie carries CSRF and `return_to` across the cutover | The port does not read it. Port forms use `_csrf_token` | avoids an AES-GCM session codec for one stale form | browsers with open forms at cutover | ADR-010 | M-36, C-21 | pending |
| DV-07 | `REDIS_URL`, `WEB_CONCURRENCY`, `RAILS_MAX_THREADS`, `RAILS_MIN_THREADS`, `PIDFILE` size processes. `JOB_CONCURRENCY` is unread. SIGPROF dumps threads. There is no Redis process | Redis retired; BEAM schedulers replace process sizing | operators who set these variables; external-`REDIS_URL` users (unknown) | ADR-018, ADR-006 | M-55, M-58, R-04, R-06, R-07, C-59, C-60 | pending |

| DV-09 | `return_to` stores the full `request.url` | Stores path and query only, and redirects only to local paths | open-redirect hardening | users redirected after login | ADR-010 | M-36 | pending |
| DV-10 | The login limit window starts at the first attempt (10 per 3 min per IP) | Hammer clock-aligned fixed windows: up to 20 attempts can land across one window edge | framework default instead of a hand-rolled limiter.
