# Runtime — ONCE Campfire

Source: `~/Projects/campfire-bench/once-campfire-elixir/reference` @ `90b3300` · Deploy model: **self-hosted single container** (one Docker image per install: ONCE installer or plain `docker run`; one host; all state on the `/rails/storage` volume). Release pipeline publishes multi-arch images (amd64/arm64) to `ghcr.io/basecamp/once-campfire` with semver tags (`.github/workflows/publish-image.yml`) and to `registry.once.com/campfire` (`bin/release`).

Key fact: everything (web, Redis, workers) runs **inside one container**, supervised by a tiny Ruby process monitor (`bin/boot`) that reads `Procfile` and **TERMs all children when any child exits** (traps `CLD`) — so any process crash restarts the whole container via Docker's restart policy. Redis runs with **no persistence** (`config/redis.conf`: `appendonly no`, `save ""`), so every Redis role, including the Resque queue, is lost on every container restart.

## Storage, Search, Mail, Push, Observability

- **File storage**: local disk only, `storage/files` inside the volume (R-28). S3/GCS/Azure are commented out — not a contract. `storage/` subdirs created at boot (`config/initializers/storage_paths.rb`: `storage/db`, `storage/files`). Thruster also keeps state under the volume (ACME certs; Thruster default `STORAGE_PATH=storage/thruster` — inferred from thruster 0.1.23 defaults, not in repo): **losing it on upgrade would re-issue certificates and may hit Let's Encrypt rate limits**.
- **Search**: SQLite FTS5 (R-27); recent searches capped at 10 per user (`Search#trim_recent_searches`).
- **Mail**: none. `actionmailer`/`actionmailbox` are transitive only; no `app/mailers`; layouts are scaffold leftovers → DELETE (no outbound mail contract; password reset is the admin CLI).
- **Web Push**: VAPID keys from `VAPID_PRIVATE_KEY`/`VAPID_PUBLIC_KEY` env, fallback to Rails credentials `vapid.*` (`config/initializers/vapid.rb`); subject `mailto:support@37signals.com`; payload `{title, options: {body, icon: account_logo_path, data: {path, badge}}}`, urgency high. Changing keys invalidates all subscriptions (documented, docs/self-hosting.md) → keys are a kept operational contract.
- **Observability**: logs to STDOUT, tagged with `request_id`, level `RAILS_LOG_LEVEL` (info), `/up` silenced, `LogScrubbingFormatter` redacts bot keys in path segments `/rooms/:id/:bot_key` (security contract, `lib/rails_ext/log_scrubbing_formatter.rb`) plus `filter_parameter_logging`. Sentry (`SENTRY_DSN`, disabled with `SKIP_TELEMETRY`, release = `GIT_REVISION`, `send_default_pii=false`) → `sentry` Elixir SDK with the same env vars. No metrics or tracing.
- **HTTP caching**: assets `public, max-age=30d` (production.rb, second assignment wins), avatars/logos ETag + `stale_while_revalidate`, QR codes 1 year, messages index `fresh_when`. These are wire behaviors; MAP.

## Questions

1. Q1 (R-02): Which Thruster behaviors/env vars does the ONCE installer depend on (ports, `TLS_DOMAIN`, cert storage path, `/up` probing)? Choose the Elixir ACME solution and whether existing certs under the volume are reused.
2. Q2: Is `RAILS_MASTER_KEY`/encrypted credentials used by any self-hosted install, or only by 37signals' own deployment (`.env.erb` uses 1Password/MRSK)? If only internal → retire.
3. Q3 (R-24, hooks): With Oban persisting jobs inside the SQLite snapshot, should restore discard `available`/`executing` jobs (to avoid re-posting webhooks/pushes) or replay them?
4. Q4 (R-10): Is the source-ZIP export to once-store hosts still part of the product contract (ONCE "own the source")? If yes, the Elixir build needs an equivalent artifact.
5. Q5 (R-30): Webhook today has no retry and no idempotency key; keep `max_attempts: 1` or approve retries with a delivery id header (guarantee change, needs approval)?
6. Q6 (R-05): Keep `memberships.connected_at/connections` columns (DB-backed presence used by push/unread) or derive from `Phoenix.Presence` in memory? Affects schema compatibility and coexistence.
