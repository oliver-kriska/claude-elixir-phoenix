## Summary

Slice 00 builds the thinnest Elixir/Phoenix skeleton that slice 02 ("post a message and deliver it live") needs. It contains:

- the supervision tree;
- a single-writer Repo plus a read-only Repo over the legacy SQLite file, opened in place;
- legacy Ecto schemas for the tables 02 touches;
- a minimal boot-time schema gate;
- the `oban_jobs` table, with Oban Lite started but no queues;
- a read-only auth edge that recognizes a legacy `session_token` cookie.

It replaces the legacy `bin/start-app` → `db:prepare` → Puma boot path only far enough to serve one authenticated request. It must leave the file bootable by the pinned Rails image, with Rails' `schema_migrations` untouched (C-01). It also measures the legacy performance baseline that ADR-000's "no regression" goal depends on. Verification is the C-01 round-trip witness on a pinned-image-created DB, cookie vectors 1–2, and a committed baseline table.

### Edge Cases (2/2)
- **Negative probes**:
  - The reader Repo rejects an `INSERT`.
  - A tampered, wrong-purpose, expired or rotated-key cookie is anonymous.
  - A valid cookie whose `sessions` row is deleted is anonymous.
  - A cookie signed with a port salt (`campfire/px/*`) does not verify as `session_token`.
  - Port migrations never insert into Rails' `schema_migrations`.
- **Failure modes**:
  - A Rails ledger that is behind, ahead or holds unknown versions halts boot with no DDL; the VM exits, matching `bin/boot`.
  - A missing `SECRET_KEY_BASE` halts boot.
  - A foreign process (backup, `sqlite3` CLI) holding the write lock gives a bounded 5 s busy wait, then an error. It does not hang.
  - FTS5 missing halts boot.
- **Crash windows**:
  - A crash during the port-only `oban_jobs` migration rolls back, because SQLite DDL is transactional. The next boot re-runs it, and `ecto_schema_migrations` never records a half-applied version.
  - A crash between the schema gate and Oban start leaves no partial state.
- **Concurrency**: pool size 1 serializes all writes. Under a test, two concurrent writes queue instead of raising `SQLITE_BUSY`.
- **Rollback**: after the port has run, the pinned image boots and ignores `ecto_schema_migrations` and `oban_jobs`.

## Binding Decisions

- DECISION (ADR-000, ASSUMED): Replacement cutover. The port opens `/rails/storage/db/production.sqlite3` in place. No destructive DDL, column reuse or triggers while the rollback window is open (it has no end date while ADR-000 is ASSUMED).
- DECISION (ADR-003, proposed): `Campfire.Repo` is the only writer:
  - `pool_size: 1`, `default_transaction_mode: :immediate`, `journal_mode: :wal`, `synchronous: :normal`, `foreign_keys: :on`;
  - `busy_timeout: 5_000` as an adapter option, never a PRAGMA;
  - `migration_source: "ecto_schema_migrations"`.

  `Campfire.Repo.Read` is read-only with `pool_size: min(schedulers, 8)`. Oban uses the writer.
- DECISION (ADR-003, proposed): every legacy datetime column uses `Campfire.Types.RailsTime`, which writes Rails' UTC text format with `.ffffff` only when usec > 0. The global `datetime_type` stays `:iso8601`, for Oban only.
- DECISION (ADR-003, proposed): enums and strings are stored as-is:
  - `role` `[member: 0, administrator: 1, bot: 2]`;
  - `status` `[active: 0, deactivated: 1, banned: 2]`;
  - nullable involvement strings, where "visible" is `involvement != 'invisible'` (NULL excluded);
  - STI `rooms.type` strings;
  - polymorphic `record_type` as an `Ecto.Enum`, falling back to `:string` if the 01 probe finds other values;
  - `accounts.settings` as `:map` with a defaults accessor that preserves unknown keys.
- DECISION (ADR-004, ASSUMED): port-only DDL runs through `Ecto.Migrator` under `ecto_schema_migrations`, with versions greater than `20251212154340`, additive only. Port versions are never mirrored into Rails' `schema_migrations`.
- DECISION (roadmap, auto): in slice 00 the BootMigrator only gates. Any Rails ledger other than the 15 versions up to `20251212154340` halts boot. RailsMigrator, the fresh-install baseline SQL and the pre-migration `VACUUM INTO` backup are slice 17.
- DECISION (ADR-006 ASSUMED + roadmap, auto): Oban 2.24 with `Oban.Engines.Lite` on the writer, `Oban.Notifiers.PG` (Erlang process groups, not PostgreSQL), and `oban_jobs` created by the first port-only migration. Oban starts with `queues: []`. Queues, plugins and workers are slice 08.

## Research Findings

### Approaches Found

#### Approach 1: Two Repos over the legacy file, a custom Rails time type, a gate-only boot migrator and a read-only Rails cookie codec (accepted design, ADR-003/004/010)
- **Thesis**:
  - One writer with `BEGIN IMMEDIATE` matches Rails' own SQLite discipline and removes `SQLITE_BUSY` between BEAM processes.
  - `RailsTime` keeps text ordering identical across Rails-written and port-written rows.
  - A separate Ecto migration ledger keeps Rails' `schema_migrations` truthful, so rollback works.
  - Reading the Rails cookie means nobody is logged out at cutover.
- **Antithesis**:
  - Every write, and later every Oban fetch and ack, shares one connection. Writer checkout queue time becomes a performance-gate metric (ADR-006).
  - The cookie codec's PBKDF2 and HMAC parameters are `needs-vector` until the pinned image produces them.
  - The project owns a Rails-format codec indefinitely.
- **Key files**:
  - `lib/campfire/application.ex`, `lib/campfire/repo.ex`, `lib/campfire/repo/read.ex`
  - `lib/campfire/types/rails_time.ex`, `lib/campfire/release/boot_migrator.ex`
  - `lib/campfire/compat/rails/{message_verifier,session_cookie}.ex`, `lib/campfire/scope.ex`
  - `lib/campfire_web/auth.ex`
  - `priv/repo/migrations/*` (port-only)

#### Rejected: `datetime_type: :text_datetime` (KB default) or `:iso8601` on legacy columns
- **Why rejected**: `:text_datetime` drops microseconds and breaks ordering within one second; `:iso8601` writes `T…Z`, which Rails text comparison misorders (ADR-003).

#### Rejected: Port the 15 Rails migrations into Ecto's ledger, or run `rails db:migrate` from a Ruby runtime in the image
- **Why rejected**: the first is a second record of the same fact that can disagree with Rails' table. The second conflicts with the charter goal of removing Ruby (ADR-004).

#### Rejected: phx.gen.auth tokens with a one-way legacy reader
- **Why rejected**: after a rollback every user would be logged out, which breaks ADR-000 Identity (ADR-010).

## Dead Ends

- DEAD-END: `ecto_sqlite3` `:text_datetime` or `:iso8601` for legacy datetime columns. Use `Campfire.Types.RailsTime` (ADR-003).
- DEAD-END: a pooled writer, or `busy_timeout` set as a PRAGMA (ADR-003; `kb/sqlite-on-beam.md`).
- DEAD-END: Ecto writing Rails' `schema_migrations`, or mirroring port versions into it (ADR-004).
- DEAD-END: a GenServer or hand-rolled connection owner in front of the database (`architecture.md` §8; ADR-003 alternatives).
- DEAD-END: a general Rails `MessageVerifier` with a purpose option, or reading or decrypting `_campfire_session` (ADR-011, ADR-010).
- DEAD-END: `plug_rails_cookie_session_store`. It is stale and does not cover the signed `session_token` (`architecture.md` §10).
- DEAD-END: `ago/2`, `from_now/2` or `datetime_add/3` against legacy columns (ADR-003 query rules).
- DEAD-END: comparing the baseline against our own intermediate build (`kb/performance-gates.md` P1).
