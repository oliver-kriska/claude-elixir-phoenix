## 00 Foundation: skeleton, Repo, HTTP edge
**Goal**: A Phoenix release boots from `runtime.exs` with the legacy env names and serves the Express-shaped HTTP edge: `GET /` liveness (F-15), `/images/*` (F-15), the Express HTML 404, the error envelope (F-14), and token verification in the auth plug, read-only (F-13). It does not mint tokens.
**Ledger rows**: M-01, R-26 (SHIM → CORS `*` with Express preflight), M-02, R-27 (SHIM → `ExpressBodyParser`), M-03 (MAP → router, feed before `:slug`, C-36a case-insensitive SHIM), M-04, M-05, R-15, R-21 (MAP → `Plug.Static`, `GET /`), M-06, R-28 (MAP → `FallbackController` + `LegacyErrors`), M-07, R-29, M-32 (REPLACE → `RealworldWeb.Plugs.Auth` + `Accounts.verify_token/1`, ADR-004), M-17, R-10 (MAP → Ecto schemas over the Prisma tables, `structure.sql`, ADR-003), M-27 (MAP → `runtime.exs`), M-24, M-28, M-31, R-06, R-14 (DELETE), R-01, R-02, R-03, R-24 (REPLACE → `mix release`, Docker, Logger, ADR-013).
**Contracts**: C-01 and C-06 (keep the tables, columns and SERIAL PKs), C-12, C-13 and C-14 (verify legacy HS256 tokens, `Token`/`Bearer`, every failure an exact 401), C-19 (404 `{}` / 403 `{message}`), C-31, C-32, C-33, C-34, C-35 (ETag and Express response semantics), C-36, C-36a, C-37 (env names), C-40 (logging, relaxed).
**Transition**: Replacement. The schema stays frozen and nobody runs DDL (ADR-003). Phoenix never touches `_prisma_migrations`. No writes in this slice.
**Acceptance criteria**: the F-13, F-14 and F-15 acceptance probes in `analysis/features.md`. The C-12, C-13, C-14, C-31…C-36a witnesses in `analysis/contracts.md`. A legacy-minted token from slice 01's vectors verifies.
**Exit gate**: `/rewrite:verify 00`. All obligations pass or are changed by an accepted ADR. No BLOCKER.
**Plan**: `.claude/plans/rewrite-00-foundation/` · State: blocked

## 02 Identity (riskiest core)
**Goal**: Register (F-01), login (F-02), read and update the current user (F-03), and mint tokens that both runtimes accept (F-13). This is the riskiest capability. Rollback depends on it (Node must verify Phoenix tokens and hashes), and so does every permission check.
**Ledger rows**: M-08 (MAP → `Accounts` token minting, `{user:{id}}`, 60 days, ADR-004), M-09 (MAP → bcryptjs-compatible `$2a$10$` hashes and trim rules, ADR-005), M-10 (MAP → registration changeset; check-then-insert plus unique-constraint fallback), M-34 (user half: truthy-only partial update), R-12 (unique index names), R-13 (column defaults).
**Contracts**: C-02, C-05, C-07, C-08, C-12, C-15, C-16, C-17 (`id` on every response except login), C-18, C-18a, C-30.
**Acceptance criteria**: the F-01, F-02 and F-03 probes, positive and negative. A Phoenix hash verifies under bcryptjs, and a Phoenix token verifies under jsonwebtoken (slice 01 vectors). Bad login returns the C-18a status and body that ADR-008 settles on.
**Exit gate**: `/rewrite:verify 02`.
**Plan**: `.claude/plans/rewrite-02-identity/` · State: blocked

## 09 Cutover rehearsal and rollback
**Goal**: Rehearse the Replacement cutover on a prod-shaped copy: drain Node, deploy Phoenix, run the contract smoke probes, then roll back by redeploying Node against the Phoenix-written DB.
**Transition** (`architecture.md` §9): there is one writer at a time. Schema authority stays frozen. Identity is a shared HS256 secret. The last reversible point is the first Ecto DDL.
**Acceptance criteria**: the §9 witnesses. Node `GET /api/user` with a Phoenix token returns 200. Node login with a Phoenix-made hash returns 200. `prisma migrate status` is up to date. Feeds read correctly on both runtimes (V-1). The perf gate is no regression against the slice 01 baseline.
**Exit gate**: `/rewrite:verify 09`, plus a go/no-go that requires V-2, V-3 and V-4 to be answered.
**Plan**: `.claude/plans/rewrite-09-cutover-rehearsal/` · State: blocked

## Unblock Order

The smallest set of decisions that unblocks 00 → 02 in order:

1. Accept or revise **ADR-000** A1 (Replacement) and A3 (keep sessions and hashes). This unblocks the handoff for every slice.
2. **ADR-011 / C-37a**: keep the `superSecret` fallback, or refuse to boot in prod without `JWT_SECRET` (recommended). Answer V-4 offline. This unblocks 00.
3. **ADR-014 / C-32a**: oversized-body status, 413 or 500. Only the 00 parser probe depends on it.
4. **ADR-008**, the bug-for-bug policy: C-19a (500 bodies), C-18a (login 403) and C-30 (update quirks) unblock 02; C-27 unblocks 05; C-26 unblocks 07.
5. **V-0** isolation decision for running the pinned legacy build. This unblocks 01, which every later slice's oracles depend on.
6. **V-1** `_UserFollows` direction → 03, 04 (feed) and 09.
7. **ADR-010 / C-23**, demo visibility, a product decision → 04, 07 and 08.
8. **ADR-009 / C-21**, the favorite leak (fix recommended) → 06.

Once 1 to 3 are decided and C-19a is settled, `/rewrite:roadmap --next` hands off slice 00.
