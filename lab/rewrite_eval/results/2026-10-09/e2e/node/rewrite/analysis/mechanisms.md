## High-Risk Mechanisms

### M-11 Demo-content visibility filter
**Anchor**: article.service.ts:8-67 (`buildFindAllQuery`), 416-431 (comments), tag.service.ts:4-14.
**Purpose**: anonymous users see only content by `demo = true` authors; logged-in users see demo content plus their own. Probably a guard for a shared public demo API, so spam from one visitor never reaches the others. (evidence: inferred. seed.ts creates every user with `demo:true`, auth.controller.ts:16 forces `demo:false` on registration. No comment, doc or commit explains it.)
**Guarantees**: Visibility per viewer on three read paths. Authorization: a client cannot become globally visible, because registration forces `demo:false` and `updateUser` does not accept `demo`. The filter is incomplete: `GET /articles/feed`, `GET /articles/:slug` and `GET /profiles/:username` ignore it, so a follower sees a non-demo author's articles in the feed but not in `?author=`.
**Failure history**: none recorded (single commit).
**Candidate**: UNDECIDED. If the target deployment is the public demo, MAP → one composable `visible_to/2` query function used by all three paths, and decide whether the feed gap is intended. If it is a private deployment, DELETE needs the product owner to confirm that real users should see each other's content.
**Why not MAP blindly**: this is a product rule that looks like a bug. Porting it to a private deployment hides every real user's articles and comments from everyone else; dropping it on the public demo exposes spam.

### M-07 / M-08 JWT verification and issuance
**Anchor**: auth/auth.ts:4-26, auth/token.utils.ts:3-6.
**Purpose**: stateless API authentication per the RealWorld spec (documented: JSDoc `@auth`; the charter names `Authorization: Token <jwt>` as must-keep).
**Guarantees**: HS256 with `JWT_SECRET`; claims `{user:{id}}`, `iat`, `exp = iat + 60d`; accepts both `Token` and `Bearer`; no revocation. Every `GET/PUT /user` returns a fresh token (sliding renewal for clients that store it). Optional routes reject invalid or expired tokens with 401 instead of treating the caller as anonymous (express-jwt behavior, inferred). A valid token for a deleted user makes `GET /user` crash: `user` is `undefined` → TypeError → 500.
**Failure history**: none recorded. Risk: the fallback secret `'superSecret'` (auth.ts:16, token.utils.ts:4) means a deployment without `JWT_SECRET` signs tokens anyone can forge.
**Candidate**: REPLACE → Joken plugs plus a token module with identical claims and TTL, so tokens issued by legacy keep verifying during coexistence and after cutover. DELETE the fallback secret (fail at boot) with approval.
**Why not MAP to phx.gen.auth**: clients hold bearer JWTs. A cookie/session token scheme would force every user to log in again and break the wire contract.

### M-09 Password hashing and trimming
**Anchor**: auth.service.ts:41,58,85-86,111,155-156.
**Purpose**: credential storage (observed: auth.service.test.ts login tests).
**Guarantees**: bcryptjs emits `$2a$10$...`. Register and login trim the password, update does not. A user who sets `" pw "` through `PUT /user` can never log in, because login trims to `"pw"`.
**Candidate**: MAP → `Bcrypt.verify_pass(String.trim(pw), hash)`. Keeping or fixing the update-path asymmetry needs a decision (Q8); fixing it cannot break any existing hash that currently works.

### M-14 / M-15 Article write atomicity
**Anchor**: article.service.ts:197-236 (create, atomic via a Prisma nested write), 276-357 (update, two statements).
**Purpose**: replace the tag set on edit (inferred).
**Guarantees**: create is atomic. Update is not: the tags are cleared first, so a failure in the second statement leaves the article with no tags. A PUT that omits `tagList` also clears all tags; that may be intended (RealWorld clients always send `tagList`) or a bug.
**Candidate**: REPLACE → one `Ecto.Multi`. Tag upsert uses `on_conflict: :nothing` to remove the concurrent-new-tag 500. Q3 decides whether an omitted `tagList` means "keep".

### M-16 / M-17 / M-18 Legacy schema contract
**Anchor**: schema.prisma; migrations 20210924225358_initial, 20211001143221_implicit_tags, 20211221184529_deprecated_preview.
**Purpose**: the existing PostgreSQL data is must-keep (charter).
**Guarantees**: quoted PascalCase tables; camelCase columns; `TIMESTAMP(3)` naive; unique index names `Article_slug_key`, `Tag_name_key`, `User_email_key`, `User_username_key` (Ecto `unique_constraint` must name them); join tables `_ArticleToTag`, `_UserFavorites`, `_UserFollows` with `A`/`B` columns, a unique `(A,B)` index and no PK; cascades done by the DB.
**Candidate**: MAP schemas, KEEP the DB cascades. The direction of `_UserFollows` (which column is the follower) must be verified on real rows before any follow query is written (Q2). Getting it wrong silently inverts every feed and `following` flag.

### M-06 Error envelope
**Anchor**: main.ts:26-47.
**Purpose**: map errors to RealWorld JSON (observed in auth tests).
**Guarantees and quirks a port must decide on**:
- the body is whatever `message` was: `{errors:{...}}` (422/403/404), `{message:"You are not authorized..."}` (403), or `{}` (404s from article, comment and profile)
- all JWT failures → 401 `{status:'error',message:'missing authorization credentials'}`
- malformed JSON: body-parser's `SyntaxError` carries `status: 400` but no `errorCode`, so it falls through to **500** with the parser message as a JSON string
- Prisma errors (P2002 unique races, P2025 missing record) → 500 with the raw Prisma message string, which leaks internals
- unknown routes → Express default HTML `Cannot GET /x` 404 (no JSON)

**Candidate**: MAP → FallbackController + ErrorJSON that keep the 401/403/404/422 bodies byte-compatible. Turning the 500 quirks into 400/404/422 is an approved behavior change (Q9).

### M-20 Favorite response leaks user records
**Anchor**: article.service.ts:597-603, 643-649.
**Purpose**: none. It diverges from `articleMapper` used by every other article endpoint (inferred).
**Guarantees**: each favorite/unfavorite response includes `favoritedBy[]` with every favoriting user's `id`, `email`, `password` (bcrypt hash), `bio`, `image` and `demo`, plus the article's `id` and `authorId`.
**Candidate**: REPLACE → the standard `ArticleJSON`. This drops keys from a wire response, so Iron Law 7 requires a recorded approval even though no legitimate consumer is plausible. Consumer evidence needed: front-end code or access logs that read `favoritedBy` (Q10).

### M-13 Slug generation
**Anchor**: article.service.ts:178, 317.
**Purpose**: a URL key derived from the title; the `-{authorId}` suffix makes collisions per author (inferred).
**Guarantees**: slugify@1.6 defaults keep case and characters such as `.`, `(`, `!`, `:`, `@`, and strip others through its charmap. Existing slugs are stored, so only **new** slugs depend on the algorithm. A title edit changes the slug, which breaks bookmarked URLs.
**Candidate**: MAP with a ported algorithm, plus characterization tests on sample titles. A different slug algorithm only changes new URLs, but still needs approval because it changes the collision rule.

## Implicit Framework Behavior

Guarantees the legacy stack provides without code, which the port must re-provide on purpose:

- **Prisma nested-write transactions** (M-15): a single `create`/`update` with nested `connectOrCreate` is atomic. Ecto needs an explicit `Ecto.Multi` or `Repo.transact/2`.
- **Idempotent `connect`/`disconnect`** on implicit m-n tables (M-16, M-23). Ecto inserts need `on_conflict: :nothing`, otherwise they raise on the `(A,B)` unique index.
- **DB defaults applied because the client omits fields**: `User.image` default URL, `demo=false`, `createdAt/updatedAt = CURRENT_TIMESTAMP` (M-17, M-33).
- **`JSON.stringify` date format**: `2024-01-04T10:00:00.000Z` (3-digit ms, `Z`). Ecto `:utc_datetime_usec` would emit 6 digits (M-19). `undefined` keys are dropped, which matters for `getCommentsByArticle` when the article is missing: it returns `{comments: undefined}`, serialised as `{}`.
- **Express routing defaults**: case-insensitive, trailing slash optional, first-match ordering (M-03).
- **express-jwt**: verifies any token present, even on optional routes; decoded payload in `req.auth` (M-07, M-32).
- **body-parser 100kb JSON limit** → 413 (M-02).
- **cors() defaults**: `Access-Control-Allow-Origin: *`, preflight 204 (M-01).
- **Express default 404** is HTML, not JSON (M-06).
- **Prisma connection pool** (default `num_cpus*2+1`) → Ecto `pool_size` (M-24).
- **No transactions anywhere else**: every check-then-act (uniqueness M-10, slug M-13, ownership M-12) is racy today. The DB unique indexes are the only real guarantee, and they surface as 500s.
