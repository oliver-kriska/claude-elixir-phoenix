## Summary

Create the Phoenix 1.8 JSON-only project `conduit` in this workspace. Configure it from fail-closed runtime env vars, and open the kept legacy SQLite file through one writer Repo with legacy-compatible durability. Add Corsica CORS with the configured origins and the secure headers on the `:api` pipeline. This replaces Django's `runserver`, the WSGI entry, the hard-coded settings and the `corsheaders` middleware (R-01, R-02, M-36, C-44, M-31, M-32). It must keep the C-31 origin defaults and the R-10 file as the system of record. Tests verify it: boot, config-failure, CORS preflight and PRAGMA checks, scored by `/rewrite:verify 00a`.

Status stays IN_PROGRESS because consequential decisions this slice depends on are still ASSUMED, proposed or pending (see Open Questions).

### Edge Cases (1/2)
- **Boot failures:** a missing var, a short secret, or `*` in `CORS_ORIGINS` → the release refuses to start.
- **Lock fencing:** another process holds a write lock on the file → `BEGIN IMMEDIATE` at boot returns busy after 5 s, and boot refuses to start. Fencing per architecture §10.
- **PRAGMA defaults:** the `foreign_keys` default differs between ecto_sqlite3 0.22 and 0.25 (VO-04). The boot log makes it visible.
- **Gap:** WAL and backup interaction is untested until DV-22 is decided and slice 09 rehearses it.

## Research Findings

### Approaches Found

#### Approach 1: Phoenix 1.8 JSON-only generator + ecto_sqlite3 writer Repo + runtime.exs fail-closed (ADR-001, ADR-003, ADR-011)
- **Thesis**: conventional Phoenix for a team of unknown Elixir experience. It keeps the legacy SQLite file and the legacy durability (`synchronous: FULL`), and removes every hard-coded secret.
- **Antithesis**: SQLite allows one writer. Writer contention is unmeasured (VO-12). WAL changes the backup procedure (DV-22).
- **Key files**: `mix.exs`, `config/runtime.exs`, `lib/conduit/repo.ex`, `lib/conduit/boot.ex`, `lib/conduit_web/endpoint.ex`, `lib/conduit_web/router.ex`

#### Rejected: X-01 Bare Plug.Router on Bandit
- **Why rejected**: the route table, pipelines and fallback would all be rebuilt by hand (ADR-001).

#### Rejected: X-02 Adding Oban "for later"
- **Why rejected**: no durable work exists, and an unused queue adds SQLite writer contention (ADR-001).

## Dead Ends

- DEAD-END: X-01 Bare Plug.Router instead of Phoenix — rebuilds framework features by hand (ADR-001)
- DEAD-END: X-02 Oban or PubSub without a legacy mechanism needing them — adds SQLite writer contention (ADR-001)
- DEAD-END: X-03 Deriving the JWT key from SECRET_KEY_BASE — couples rotations (ADR-011)
- DEAD-END: X-04 Reusing the legacy committed SECRET_KEY anywhere — security defect C-14 (ADR-000, DV-01)
- DEAD-END: X-05 `synchronous: :normal` — silent durability downgrade vs legacy FULL (ADR-003)
